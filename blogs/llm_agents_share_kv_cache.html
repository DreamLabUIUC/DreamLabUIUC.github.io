Can LLM Agents Share the KV-Cache Instead of Text Messages?

Agents built on the same model can hand each other their internal memory instead of writing messages. That memory turns out to be cheaper to read, can be trained, and needs checking.

By Peng Kuang, Ye Yu, Xiaopeng Yuan, Haibo Jin, Haohan Wang, and others · October 19, 2026 · About our NeurIPS 2026 and ICML 2026 papers and two preprints

  • KV-PRM paper
  • DiffMAS paper
  • ReLAT paper

Can LLM agents share the KV-cache instead of text? Yes, when they run on the same model: one agent can hand the next its KV-cache, the internal memory a transformer keeps while it writes, instead of a written message. Most multi-agent LLM systems still talk in text, which means every agent re-reads the whole history and the rich internal state of the sender is squeezed into words. In KV-PRM: Efficient Process Reward Modeling via KV-Cache Transfer for Multi-Agent Test-Time Scaling (Peng Kuang, Haibo Jin, Xiaoyu Han, Yanli Wang, Xiaopeng Yuan, Ye Yu, Kaidi Xu and Haohan Wang, University of Illinois Urbana-Champaign, NeurIPS 2026), a reward model that reads this cache scored agents' reasoning 37 times faster than one that re-reads the text, with matched or better accuracy. This post explains the KV-cache in plain words and walks through three ways our lab has used it: to score agents, to train how they communicate, and to check latent reasoning that no one can read.

Key findings

  • KV-PRM (Kuang et al., University of Illinois Urbana-Champaign, NeurIPS 2026) scores multi-agent reasoning by reading the KV-cache the agents already produced, cutting per-sequence scoring latency from 172.0 ms to 4.6 ms (37×) and memory by up to 34.2× versus a text-based process reward model with Qwen3-8B on 4,096-token trajectories.
  • Despite using roughly 1/900 to 1/4,900 of the scoring compute, KV-PRM matched or beat the text-based reward model on average: under MCTS search on MATH and AIME 2024 it averaged 49.03% accuracy versus 47.42%, with Qwen3 models from 0.6B to 8B parameters.
  • In the preprint Learning to Communicate (Yu et al., 2026), training the KV-cache channel between agents (DiffMAS) raised Qwen3-8B from 50.0% to 76.7% on AIME 2024 and from 39.9% to 60.1% on GPQA-Diamond, after fine-tuning on only 210 math problems; text-based agents reached 50.0% and 43.4%.
  • In the preprint Closing the Loop on Latent Reasoning (Yuan et al., 2026), requiring a latent thought to reconstruct the original question at test time (ReLAT) raised Qwen3-8B on AIME 2024 from 56.7% with training-free latent agents (LatentMAS) to 73.3%.

What is the KV-cache, in plain words?

A large language model writes one token at a time. To choose each new token, every layer of the transformer looks back at all earlier tokens through attention, and for that it needs a "key" and a "value" vector for each of them. Recomputing these for the whole history at every step would be wasteful, so the model stores them as it goes. That store is the KV-cache: a key and a value for every token, at every layer. It is a running memory of everything the model has read and written, in the model's own internal language.

Two facts make the KV-cache interesting for multi-agent systems. First, it exists anyway: generation produces it whether or not anything else uses it. Second, it holds far more than the text it produced. The KV-PRM paper proves, under the linear representation hypothesis, that expressing a length-L cache losslessly in text would take on the order of d·L / log|V| tokens, where d is the model's hidden size and |V| its vocabulary size. Text is a lossy summary of the cache, not the other way round.

Key terms

KV-cache (key-value cache)
The key and value vectors a transformer stores for every token it has processed, at every layer, so it can generate the next token without recomputing the history.
Multi-agent LLM system
Several LLM "agents" with different roles, such as planner, solver and verifier, that pass work to each other to solve one problem.
Latent communication
Agents exchanging internal representations, such as hidden states or KV-caches, instead of decoded text.
Process reward model (PRM)
A model that scores intermediate reasoning steps, so a search procedure can keep promising partial solutions and drop poor ones.
Test-time scaling
Spending more compute at inference, for example by sampling many candidate solutions and searching over them with beam search or Monte Carlo Tree Search (MCTS), to get better answers.
Verify token
In KV-PRM, a single extra token ("?") that attends to the existing KV-cache and outputs the reward, read from the probabilities of "+" and "−".

Why do multi-agent LLM systems waste compute passing text?

In a text-based multi-agent system, each agent decodes its thinking into words and the next agent reads those words from scratch. The sender's internal state is compressed into tokens, and every reader pays again to encode the growing history. The cost is sharpest when something has to read whole trajectories many times, as a process reward model does during search: with beam width W over D agent steps it is called at least W·D times, and each text-based call costs time that grows with the square of the trajectory length. The KV-PRM paper notes that when the reward model and the agents are the same size, scoring roughly doubles the system's total compute.

How does KV-cache sharing speed up multi-agent LLM systems?

KV-PRM replaces the text-reading reward model with one that reads the cache. After an agent finishes, its KV-cache is already sitting in memory. KV-PRM appends a single verify token and runs it through the same base model with a small LoRA adapter switched on; the adapter has learned to read the cache and output a score. Generation itself is untouched, because the adapter is off while agents write. The scoring cost drops from growing with L² to growing with L, the trajectory length: about 5,000 times fewer operations for a typical 5,000-token trajectory. A second theorem in the paper shows that extra verify tokens bring exponentially diminishing returns, which the experiments confirm: one token already captures most of the signal.

The authors trained KV-PRM and an otherwise identical text-based reward model (same LoRA settings, same MCTS-generated labels from the MATH training split) and plugged each into a sequential team of four Qwen3 agents (Reader, Planner, Solver, Verifier). Results from Table 1 of the KV-PRM paper:

The average covers MATH with Qwen3-0.6B, 4B and 8B and AIME 2024 with Qwen3-4B and 8B. On wall-clock time, measured on an NVIDIA GH200 GPU, KV-PRM was 15 to 37 times faster per sequence, with the gap growing for longer trajectories and larger models; at 8B and 4,096 tokens one scoring call took 4.6 ms instead of 172.0 ms. It is not better everywhere: on GSM8K under MCTS it averaged 58.45% against 58.58% for the text-based model, and a few single cells are lower. Two further results stand out:

  • A smaller text verifier is not the answer. Scoring Qwen3-8B's search trees on MATH, text-based reward models of 0.6B, 4B and 8B all scored below the 8B KV-PRM, which reached 68.0% at about 3,000 times lower cost than the 8B text model.
  • The cache can be steered. Because KV-PRM's score is differentiable with respect to the cache, the authors nudged the cache by gradient ascent at each agent handoff, with no search at all. This "KV Steering" proof of concept added 1.6 points on MATH with Qwen3-4B and 3.3 points on AIME 2024 and 2025 with Qwen3-8B.

Can agents learn how to communicate through the KV-cache?

Sharing the cache removes text from the handoff, but most existing methods leave the channel itself fixed: the receiving agent gets whatever the sender happened to store. Learning to Communicate: Toward End-to-End Optimization of Multi-Agent Language Systems (Ye Yu, Heming Liu, Haibo Jin, Xiaopeng Yuan, Peng Kuang and Haohan Wang, arXiv preprint 2026) asks whether the channel can be learned. Its method, DiffMAS, has upstream agents build one shared, growing KV trace; the final agent decodes the answer from that trace; and supervised fine-tuning with LoRA adapters is applied over the whole multi-agent trajectory, with the backbone frozen. The paper argues that because the trace is concatenated rather than overwritten, the training signal reaching early agents does not shrink with their distance from the output.

The training sets were deliberately tiny: 210 Hendrycks MATH problems for one epoch for math and science, 50 HumanEval problems for code, 700 CommonsenseQA questions for commonsense. Across Qwen3-4B, 8B and 14B, Ministral-3-8B and DeepSeek-R1-Distill-Qwen-32B, DiffMAS was best or tied for best on every benchmark reported, though the gains were smaller at 32B (70.0% versus 66.7% for a single agent on AIME 2024, and no gain on AIME 2025). Is it the communication or just the fine-tuning? The paper compares with text-based agents fine-tuned on the same data: both reached 76.7% on AIME 2024, but DiffMAS was ahead on AIME 2025 (56.7% vs 50.0%), GPQA-Diamond (60.1% vs 53.5%) and OpenBookQA (85.8% vs 81.2%). Two more observations: ten latent communication steps worked best (76.7%), and longer traces hurt (63.3% at 40 steps); and the trained channel decoded more steadily than the training-free one, with mean perplexity 1.24 against 1.31 for LatentMAS on AIME 2024.

How do you check a latent thought you cannot read?

Moving reasoning out of text has a cost: a text message that drops a constraint of the problem is visibly wrong, while a latent state that drops the same constraint looks like any other. Closing the Loop on Latent Reasoning via Test-Time Reconstruction (Xiaopeng Yuan, Haibo Jin, Ye Yu, Peng Kuang, Lijun Yu, Yushun Dong and Haohan Wang, arXiv preprint 2026) proposes a simple check: if a latent thought faithfully represents the question, the model should be able to rebuild the question from it. Strictly, this is latent reasoning inside one model rather than KV-cache sharing between agents: ReLAT's latent thought is a short sequence of 16 soft token embeddings. But it addresses the same weakness, and it is compared directly against LatentMAS, which passes KV-cache states between agents.

ReLAT (Reconstruction-Guided Latent Reasoning At Test Time) runs a Question → Latent Thought → Question loop for each test problem, updates temporary LoRA weights for 16 steps to lower the reconstruction loss, answers the question, and then resets the weights. On AIME 2025 it used about 10,280 tokens per question against about 64,381 for three rounds of text-based Self-Refine, an 84.0% reduction, while scoring 63.3% against 53.3%.

What are Agent Primitives, and how do they use the KV-cache?

The earliest of these papers is Agent Primitives: Reusable Latent Building Blocks for Multi-Agent Systems (Haibo Jin, Peng Kuang, Ye Yu, Xiaopeng Yuan and Haohan Wang, ICML 2026). It breaks multi-agent systems into three reusable blocks, Review, Voting and Selection, and Planning and Execution, whose internal agents communicate through the KV-cache, with an Organizer agent that composes them for each query. Across eight benchmarks and five open-source backbones, these systems improved average accuracy by 12.0–16.5% over single agents and used about 3–4× fewer tokens and less latency than text-based multi-agent systems, at only 1.3–1.6× the cost of a single agent. The full story is in our Agent Primitives project post. KV-PRM's KV Steering experiment cites this work: it optimizes, by gradient, the kind of latent messages that Agent Primitives showed agents can exchange.

What else do we know about KV-cache communication between agents?

  • Training-free latent collaboration. Latent Collaboration in Multi-Agent Systems (Jiaru Zou, Ruizhong Qiu, …, James Zou, Mengdi Wang and Ling Yang, ICML 2026 Spotlight) introduced LatentMAS, in which agents think in last-layer hidden states and share a latent working memory, with no training. Across nine benchmarks it reported up to 14.6% higher accuracy than single agents and text-based systems, 70.8–83.7% fewer output tokens and 4–4.3× faster inference. LatentMAS is the main baseline in our DiffMAS and ReLAT papers; our results suggest that training the channel (DiffMAS) or checking it (ReLAT) adds accuracy on top of the training-free approach, at the cost of a training step.
  • Communication between different models. Cache-to-Cache: Direct Semantic Communication Between Large Language Models (Tianyu Fu, Zihan Min, Hanling Zhang, Jichao Yan, Guohao Dai, Wanli Ouyang and Yu Wang, ICLR 2026) learns a network that projects and fuses one model's KV-cache into another's, so even different model families can communicate. It reported 6.4–14.2% higher average accuracy than individual models, about 3.1–5.4% over text communication, and a 2.5× average latency speedup. Our methods assume agents share a model; C2C tackles the harder heterogeneous case. In the DiffMAS paper's reasoning benchmarks, C2C scored lower, which the authors attribute to its training data (OpenHermes-2.5, mainly instruction following) not matching long reasoning tasks.
  • Reusing caches for speed. KVCOMM: Online Cross-context KV-cache Communication for Efficient LLM-based Multi-agent Systems (Hancheng Ye, Zhengqi Gao, …, Danyang Zhuo and Yiran Chen, NeurIPS 2025) attacks the same waste from the systems side: agents re-process overlapping context, and caches cannot simply be reused because each agent's prefix differs. KVCOMM corrects the cache offsets with a pool of anchor examples, without training, and reported over 70% cache reuse and up to 7.8× faster prefill in a five-agent setting (time to first token from about 430 ms to about 55 ms). It speeds up reading shared context; KV-PRM speeds up scoring it. The two are complementary.
  • Process reward models for agents. Let's Verify Step by Step (Hunter Lightman, Vineet Kosaraju, …, Karl Cobbe, OpenAI, 2023) showed that rewarding each reasoning step beats rewarding only the final answer on MATH, and released 800,000 step-level labels (PRM800K). MASPRM: Multi-Agent System Process Reward Model (Milad Yazdani, Mahdi Mostajabdaveh, Zirui Zhou and Ying Xiong, 2025) brought step-level reward models to multi-agent systems, trained from MCTS rollouts without human step labels, and improved search on GSM8K, MATH, MMLU and LogiQA. Both score text; KV-PRM keeps their training recipe and changes what the scorer reads.
  • The privacy question. LCGuard: Latent Communication Guard for Safe KV Sharing in Multi-Agent Systems (Sadia Asif, Mohammad Mohammadi Amiri, Momin Abbas, Prasanna Sattigeri and Karthikeyan Natesan Ramamurthy, 2026) points out that a shared cache also carries an agent's inputs and intermediate reasoning, and that an adversarial decoder may reconstruct sensitive content from it. It learns transformations of the cache that reduce this leakage while keeping task performance. The richer information that makes the cache useful is the same information that makes it worth guarding.

What this does not show

  • Same model, same family. KV-PRM requires the reward model and the agents to share an architecture, and DiffMAS and Agent Primitives use one backbone for all agents. Mixing model families needs a translation layer such as Cache-to-Cache.
  • Mostly math, open models up to 32B. KV-PRM is tested on MATH, GSM8K and AIME with Qwen3 up to 8B; DiffMAS and ReLAT add science, code and commonsense benchmarks and models up to 32B. Closed API models do not expose their caches at all.
  • Small benchmarks, large swings. AIME 2024 and AIME 2025 have 30 problems each, so one problem moves accuracy by 3.3 points. The largest gains reported here (for example +26.7 points for DiffMAS and +16.6 for ReLAT on AIME 2024) amount to 8 and 5 problems.
  • Tuning on the test benchmarks. ReLAT's learning rate and thought length are ablated on AIME 2024 and 2025 themselves, and DiffMAS's number of communication steps on AIME 2024. The two preprints have not yet been peer reviewed.
  • Opaque by design. Latent messages cannot be read by a person. ReLAT's reconstruction check is a necessary condition for a faithful latent thought, not proof of correct reasoning, and a shared cache raises privacy questions that text logs do not.
  • KV Steering is preliminary. Its gains are a few points on small benchmarks and are presented by the authors as a proof of concept.

Frequently asked questions

Can LLM agents share the KV-cache instead of text?

Yes, when the agents run on the same model or a compatible one. The receiving agent attends to the sender's cached keys and values directly instead of reading a decoded message. In our papers, this has been used to score reasoning (KV-PRM, NeurIPS 2026), to train how agents communicate (DiffMAS, preprint) and to build reusable multi-agent blocks (Agent Primitives, ICML 2026).

What is the KV-cache in an LLM?

The KV-cache is the set of key and value vectors a transformer stores for every token it has already processed, at every layer. It lets the model generate the next token without recomputing the whole history, and it exists as a by-product of generation whether or not anything else uses it.

How does KV-cache sharing speed up multi-agent LLM systems?

It removes repeated re-reading of the same history. A text-based process reward model re-encodes the whole trajectory at a cost that grows with the square of its length; KV-PRM reads the existing cache with one extra token. With Qwen3-8B on 4,096-token trajectories this cut scoring latency from 172.0 ms to 4.6 ms, 37 times lower, and memory per sequence by up to 34.2 times.

Is latent communication between agents less reliable than text?

It can be, because a latent state cannot be read and checked the way text can. Two of our preprints address this: DiffMAS trains the latent channel, which gave lower perplexity than training-free latent communication (1.24 vs 1.31 on AIME 2024), and ReLAT checks that a latent thought still lets the model rebuild the original question. Neither is a guarantee of correct reasoning.
